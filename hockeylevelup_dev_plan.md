# HockeyLevelUp — план разработки по фазам

Порядок построен так, чтобы после фазы 5 уже была полностью рабочая
петля "план → тренировка → результат", которую можно потыкать руками —
а дальше каждая следующая фаза достраивает её новым слоем, не ломая
предыдущий.

---

## Фаза 0 — каркас проекта

- FastAPI-приложение, структура папок по доменам (`routers/services/
  repositories/schemas/ai/`).
- Postgres (async, SQLAlchemy) + Alembic-миграции.
- Docker-compose для локальной разработки: Postgres + RabbitMQ сразу,
  не позже — событийная логика будет нужна уже в фазе 5.
- Auth: регистрация/логин/JWT.
- `User` с базовой анкетой (рост, вес, возраст, позиция, стаж).

**Результат:** можно зарегистрироваться и получить токен.

---

## Фаза 1 — каталог упражнений (минимальный, без AI)

- Модели `Exercise` (name, category on_ice/off_ice, phase
  warmup/main/cooldown, target_stat, difficulty_level, equipment_type).
- Наполнение вручную 15-20 упражнений: по несколько на каждую фазу и
  каждый вид оборудования (зал/дом/вес тела) — тот самый ручной
  контент, который дороже кода.
- Эндпоинты чтения каталога (для дебага и админки).

**Результат:** есть на чём собирать тренировки.

---

## Фаза 2 — объявление недели и детерминированная сборка тренировки

- Эндпоинт объявления дней (лёд/сухая/отдых) с дефолтным шаблоном.
- Сборка `TrainingSession` из skeleton-конфига (доля времени по фазам).
- Main-блок **пока без AI** — простое правило: топ упражнений по
  `target_stat`, отфильтрованные по оборудованию пользователя.
- Разминка/заминка — ротация из курируемого пула.

**Результат:** пользователь объявляет неделю и получает готовую
структурированную тренировку на каждый день.

---

## Фаза 3 — выполнение и начисление (событийная шина)

- Эндпоинт завершения упражнения → публикация события в RabbitMQ.
- Обработчики: обновление характеристики + запись в историю с причиной,
  обновление streak, начисление XP.
- Эндпоинты чтения: текущие статы, история, streak.

**Результат:** первая полностью рабочая петля целиком — план,
тренировка, отметка выполнения, видимый прогресс. Дальше всё —
надстройки поверх неё.

---

## Фаза 4 — decay

- Ленивый расчёт затухания характеристики при чтении (без фоновой
  джобы по всем пользователям).
- Отображение причины изменения в истории ("decay" vs "quest_completed").

---

## Фаза 5 — тест норматива / калибровка "с нуля"

- `NormTable`, эндпоинт прохождения теста, перевод баллов в стартовые
  характеристики и `fitness_tier`.
- Режим "с нуля": дефолтный tier + сбор обратной связи после подходов
  для подстройки сложности.
- Подключение `fitness_tier` к фильтрации кандидатов в основной части.

---

## Фаза 6 — навыки и игровые пороги

- `Skill`, `SkillStatWeight` — вычисление значения навыка на лету.
- `SkillTag` на упражнениях (черновик через AI офлайн + ручная
  модерация, затем в БД).
- `SkillMilestone` — качественные пороги, экран прогресса навыка.
- Опционально: блокировка сложных упражнений до порога.

---

## Фаза 7 — выбор навыков на онбординге (спотифай-стиль)

- Экран выбора навыков для развития (мульти-select чипов).
- Подключение выбора как приоритетного фильтра в подборе основной
  части, наравне с decay и tier.
- Возможность поменять выбор позже.

---

## Фаза 8 — AI-модуль

- Изолированный сервис: контекст → structured JSON → валидация против
  списка кандидатов → fallback на детерминированную логику из фазы 2
  при сбое.
- Промпт учитывает: выбранные навыки, tier, оборудование, decay,
  историю недавних упражнений.
- Метрика `generated_by: ai | fallback` для мониторинга.

---

## Фаза 9 — периодизация

- `TrainingBlock` (фаза: накопление/интенсификация/разгрузка),
  привязка недели к блоку.
- Прогрессия сложности внутри блока, пересчёт при пропущенных неделях.
- Триггер повторного норматива на границе блока.

---

## Фаза 10 — монетизация

- Единая точка входа: проверка доступа перед AI-путём (фаза 8) —
  бесплатно fallback-логика, платно полный AI-пайплайн с
  периодизацией.
- Ничего из фаз 0-7 не режется по тарифу.

---

## Фаза 11 — админка контента и полировка

- Защищённые эндпоинты/простая админка для правки каталога, SkillTag,
  Milestone без релиза.
- UI-полировка моментов level-up/разблокировки порога/продления
  streak — дёшево по стоимости, сильно по влиянию на удержание.

---

## Как использовать этот план на практике

Каждая фаза — отдельный набор задач для Claude Code, формулируется
словами по мере прохождения ("собери эндпоинт объявления недели с
такой-то схемой"), а не пишется руками. После фазы 3 уже можно
показывать тестерам первую рабочую версию и параллельно достраивать
следующие фазы по их реакции, не дожидаясь фазы 11.
