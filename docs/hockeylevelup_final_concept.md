# IceLevel — итоговая концепция

## Идея в одном абзаце

RPG-трекер тренировок для хоккеистов-любителей. Пользователь выбирает,
какие игровые навыки хочет развивать (в духе выбора жанров в Спотифае),
заявляет дни недели, когда готов тренироваться, и получает структурную
тренировку (разминка/основная часть/заминка) под свои условия
(зал/дом/только вес тела). Прогресс выражается через характеристики и
вычисляемые из них навыки с понятными игровыми порогами-достижениями, а
не абстрактным числом. Тренировки объединяются в многонедельные
тренировочные блоки, чтобы прокачка была настоящей прогрессией, а не
топтанием на месте.

---

## 1. Онбординг

1. Регистрация, анкета: рост, вес, возраст, позиция, стаж.
2. **Условия тренировок**: зал / домашний инвентарь / только свой вес —
   влияет на фильтрацию упражнений везде дальше, редактируется в любой
   момент, может уточняться по дням при объявлении недели.
3. **Тест физподготовки или "с нуля"**:
   - тест — простые измеримые упражнения → баллы через `NormTable` с
     поправкой на возраст → стартовые характеристики и `fitness_tier`;
   - "с нуля" — дефолтный beginner-tier, первая неделя калибрует уровень
     по обратной связи пользователя после подходов ("легко/тяжело/не
     смог"), без отдельного теста.
4. **Выбор навыков для развития** (спотифай-стиль): чипы конкретных
   игровых способностей — взрывной старт, сила броска, катание в
   поворотах, силовая борьба, выносливость, игровое чтение. Можно
   выбрать несколько, можно поменять позже. Это заменяет абстрактную
   "цель" на понятный игровой язык и напрямую определяет приоритет
   упражнений в основной части тренировки.

---

## 2. Модель прогресса — три слоя

**Слой 1 — характеристики** (сила, ловкость, интеллект, выносливость):
единственное, что реально хранится и меняется. Растут от выполнения
упражнений, затухают (decay) после 1-2 недель простоя, мягко
(~2%/неделю), считаются лениво при чтении, не фоновой джобой.

**Слой 2 — навыки** (катание, бросок, силовая борьба и т.п.): не
хранятся отдельно, а вычисляются как взвешенная сумма характеристик
(`value = Σ характеристика × вес`). Веса задаются вручную по личной
экспертизе, калибруются позже по накопленным данным пользователей.

**Слой 3 — курируемый смысловой контент поверх навыков**:
- `SkillTag` на упражнениях — связывает конкретное упражнение с
  конкретным навыком и объясняет transfer на лёд ("приседания →
  мощность старта"). Это же используется в обе стороны: и как
  объяснение "почему выбрано это упражнение", и как явный вход выбора
  навыков на онбординге.
- `SkillMilestone` — качественные пороги навыка с понятным игровым
  описанием ("катание 70 → взрывной старт: первые 3 шага разгона
  заметно быстрее среднего любителя"), без псевдо-точных числовых
  предсказаний результата на льду. Часть более сложных упражнений может
  быть заблокирована до пересечения порога — прогресс открывает
  реальный контент, а не только текст.

Весь слой 3 наполняется офлайн: черновик через AI-генерацию по промпту
с ручной модерацией автора продукта, никогда не генерируется в
рантайме — защита от AI-галлюцинаций в биомеханике.

---

## 3. Структура тренировки

Тренировка = сессия из трёх фаз:

| Фаза | Кто выбирает | Персонализация |
|---|---|---|
| Разминка | курируемый пул, ротация | без AI |
| Основная часть | AI, из предфильтрованных кандидатов | под навыки-выбор, tier, оборудование, decay, блок периодизации |
| Заминка | курируемый пул, ротация | без AI |

Skeleton (доля времени на фазу) задаётся конфигом по типу тренировки
(лёд/сухая), не генерируется моделью. Кандидаты для основной части
предварительно фильтруются по оборудованию и уровню сложности **до**
AI-вызова — модель не должна сама догадываться об ограничениях
пользователя. У каждого упражнения на экране — бейдж оборудования
(зал/дом/вес тела) и опциональная подсказка-обоснование через SkillTag.

---

## 4. Недельный и многонедельный цикл

**Еженедельно**: пользователь объявляет тип дня (лёд/сухая/отдых), для
нового пользователя — с предзаполненным шаблоном по tier, для
повторного — "как на прошлой неделе" одной кнопкой.

**Мезоцикл (`TrainingBlock`)** — 3-4 недели, фаза: накопление объёма →
интенсификация сложности → разгрузка. Каждый следующий блок стартует
выше предыдущего — это и есть настоящая прогрессия. Если пользователь
пропускает недели, блок ориентируется на фактически выполненные недели,
а не на календарь. Граница блока (конец разгрузки) — естественная точка
для повторного норматива: пользователь не измотан, результат честный.
Может сработать раньше срока, если стат заметно опередил tier.

---

## 5. Бизнес-логика начисления прогресса

При выполнении упражнения одновременно: растёт характеристика,
пишется точка в историю с явной причиной, продлевается streak,
начисляется XP. Регулярная обратная связь "слишком легко/тяжело"
подстраивает сложность будущих тренировок без ожидания конца недели.

## 6. Архитектура

**Модульный монолит** на FastAPI + Postgres (async), не микросервисы —
для текущего масштаба (сотни тестеров) это избыточно, а внутренние
доменные границы всё равно позволяют выделить сервис позже, если
понадобится.

**Событийная шина** (RabbitMQ/Kafka) внутри монолита: событие "квест
завершён" публикуется один раз, а обработка статов, streak, проверки
достижений и будущих фич (fatigue-чекин, корреляционная аналитика v3)
подписываются на него независимо — ядро не меняется при добавлении
новых обработчиков.

**AI-модуль** — изолированный, один контракт (контекст на вход →
провалидированный план или сигнал fallback на выход). Тот же клиент
переиспользуется для офлайн-генерации черновиков SkillTag/Milestone.

**Контент как данные, не код** — простая админка/защищённые эндпоинты
для пополнения каталога упражнений, тегов, порогов без релиза.

**Монетизация** — единая точка входа в персонализацию: бесплатно —
детерминированный подбор по простым правилам; платно — полный AI с
историей, блоком периодизации и объяснениями. Ничего из
геймификации/прогресса/навыков не урезается на бесплатном тарифе —
только глубина персонализации подбора.

---

## 7. Осознанно вне текущего скоупа

- Двухразовые тренировки в день.
- Численные предсказания результатов на льду (только качественные
  пороги).
- Полная on-ice часть периодизации — обсуждается отдельно.
- Точная калибровка весов навыков — стартуем с интуитивных оценок.
- Ментальные визуализации, годовое макропланирование, IceSession,
  корреляционная аналитика off-ice/on-ice — бэклог v2/v3.

---

## 8. Открытый процесс

Планируется тестирование на реальной группе хоккеистов-любителей
(готовая аудитория из сотен человек) до финальной настройки
монетизации — гипотезы про ценность фич и границу платно/бесплатно
проверяются на живой реакции, а не только на проектных решениях.
